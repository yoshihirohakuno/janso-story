## 1. 設計方針

### 1.1 前提：レイヤー合成方式との関係（→ [01_game_overview.md](file:///Users/yoshihirohakuno/.gemini/antigravity/scratch/janso-story/docs/design/01_game_overview.md) 9章）

ビル外観・内観は「ベース画像1枚 ＋ Phase別レイヤー（透過PNG）」を重ねる方式で作成する。  
この方式を前提とすると、空間設計は通常の「家具配置」ではなく、将来追加される設備のための空き地（スロット）を先に確保しておく設計が中心になる。

レイアウトを考える際は、フロアを以下の3種類の領域に分けて扱う。

| 領域 | 内容 | Phaseが進んでも動くか |
| :--- | :--- | :--- |
| **固定領域** | ベース画像に焼き込まれた壁・床・建具・カウンター等 | 動かない（基本的に上書きしない） |
| **可変領域（スロット）** | 「ここに卓が置かれる」「ここに本棚が置かれる」と決まっている場所。購入前は空き床、購入後にオブジェクトレイヤーが重なる | 購入タイミングで変化 |
| **動線領域** | スロットとスロットの間、スロットと壁の間に確保する、キャラクターが歩行するための余白 | どのPhaseでも潰さない |

### 1.2 通路の基本ルール（簡易グリッド換算）

ドット絵・見下し型視点のため、厳密な実寸（cm）ではなく簡易グリッドで考える。

* キャラクター1人 ＝ 約1グリッド
* 通路（メイン動線） ＝ 最低2グリッド幅を確保（すれ違い・配膳動線を想定）
* 卓1台 ＝ 本体＋椅子4脚の引き余地を含めて約4〜6グリッドを占有

**NG例（添付背景画像 三元楼_内観背景_無人_.png の現状）：**  
4卓を2×2グリッドで均等配置し、卓と卓の間・卓とカウンターの間がほぼ隙間しかない状態。  
スロットを隙間なく並べたことで動線領域がゼロになっている。今回の設計ではこれを反面教師として扱う。

### 1.3 「初期状態は寂しい方がよい」という設計意図

ストーリー設計（[01_game_overview.md](file:///Users/yoshihirohakuno/.gemini/antigravity/scratch/janso-story/docs/design/01_game_overview.md)）・経済設計（[02_point_ryou_design.md](file:///Users/yoshihirohakuno/.gemini/antigravity/scratch/janso-story/docs/design/02_point_ryou_design.md)）・設備ツリー（[03_equipment_tree.md](file:///Users/yoshihirohakuno/.gemini/antigravity/scratch/janso-story/docs/design/03_equipment_tree.md)）を踏まえると、添付の背景画像（4卓・本棚・ソファ・カウンター完備）は Phase 1の最終形（卓を3回追加購入した後の状態）に近く、ゲーム開始時の絵としては要素が多すぎる。

開始時点は以下を意図的に欠落させる。

* 卓は1卓のみ（残り3卓分は「何もない空き床」として見せる）
* 本棚・ソファ・装飾小物は無し、またはごく簡素なものに留める
* 照明は「電球切れかけ」で画面全体がやや暗い
* カウンターにお茶・湯呑み等は無し（お茶サービス購入後に初登場）

「がらんとした空き地」を画面内に意図的に残すことで、プレイヤーに「ここに何かが増えていく」という未来の伸び代を視覚的に予感させる。

## 2. Phase 1（ボロ雀荘）内観レイアウト

**状態：** 1Fのみ・卓は購入により最大4卓まで増加・電球切れかけ

### 2.1 初期状態（ゲーム開始時点）

| 項目 | 内容 |
| :--- | :--- |
| **卓** | 1卓のみ（系列A Step0）。部屋の中心よりやや奥（カウンター側）に配置。手積み式（自動雀卓化前） |
| **椅子** | 古い・バラバラなデザイン（統一感がない＝安っぽさの表現） |
| **床** | 古い板張り・きしみ表現あり（新調前） |
| **壁紙** | 黄ばみ・劣化表現あり（変更前） |
| **本棚・ソファ** | 無し |
| **カウンター** | 板を渡しただけの簡素な見た目。お茶・湯呑み・ドリンクバー等の小物は無し |
| **照明** | 電球切れかけ。画面全体をやや暗めに、ちらつき表現があるとよい |
| **入口前** | 空きスペースとして広く取る（将来の卓スロット3つ分を確保） |
| **トイレ** | ドア・壁の劣化表現あり（修繕前） |

**設計意図：**  
入口から見て手前に大きな「歩ける空き地」を作る。これは (a) 動線確保 と (b) 将来の伸び代の視覚化 を同時に満たす。

### 2.2 卓スロットの配置と増設順

4卓まで増える前提で、スロットの位置と増設順をあらかじめ固定しておく（ベース画像に4卓分の空き地を最初から仕込んでおく必要があるため）。

```
[カウンター・受付]
─────────────────
|  Slot-B    Slot-D  |   ← 通路（2グリッド幅）
|  ─────通路─────    |
|  Slot-A    Slot-C  |
─────────────────
     [入口]
```

| 順番 | スロット | 配置理由 |
| :--- | :--- | :--- |
| 1卓目（初期） | **Slot-A** | 入口から見て奥・カウンターに近い位置。最初の1卓は「店員（プレイヤー）の目が届く特等席」として自然な位置に置く |
| 2卓目 | **Slot-C** | Slot-Aの対角ではなく横に並べる。通路を挟んで向かい合わせにならない位置を優先し、動線を分断しない |
| 3卓目 | **Slot-B** | カウンター側の奥列を埋める |
| 4卓目 | **Slot-D** | 最後に残った奥列を埋める。4卓完成時に添付背景画像とほぼ一致する状態になる |

Slot間・Slot-壁間は常に2グリッド以上の通路幅を確保する。卓が増えるたびに通路の「本数」は変わらないようにし、通路の「長さ・位置」だけが調整される設計とする。

### 2.3 設備購入 → 背景変化 対応表

#### 2.3.1 二系統の設備分類（重要）

Phase 1の設備は、背景画像の作り方の観点から2つの系統に分かれる。

| 系統 | 内容 | 購入順 | 背景画像の作り方 |
| :--- | :--- | :--- | :--- |
| **A. 順序固定系列**<br>（内装の大きな変化） | 卓追加・電球交換・トイレ修繕・床新調・壁紙新調・自動雀卓化 | 固定。前のステップを購入していないと次が選べない（購入ボタンがロックされた状態で表示される） | 背景は常に「1本道の連番」。分岐が発生しないため、組み合わせ爆発が起きない |
| **B. 自由購入系列**<br>（点的な小物追加） | お茶サービス・Wi-Fi設置・ドリンクバー設置 | 自由（プレイヤーが好きな順で購入可） | 単体オブジェクトを生成し、Aの「その時点の背景」の決まった座標に合成する。Aの進行状況と関係なく独立して合成できる |

この2系統に分けることで、「内装（A）は1本道の背景連番」「小物（B）は背景の上に重ねるレイヤー」という整理になり、画像生成・実装の両面でシンプルになる。

#### 2.3.2 系列A：内装の順序固定ステップ（背景連番）

**購入順序：** 卓追加(2台目) → 卓追加(3台目) → 卓追加(4台目) → 電球交換 → トイレ修繕 → 床新調 → 壁紙新調 → 自動雀卓化

卓追加は1台→4台の間に2回の中間段階（2台・3台）があるため、個別の背景として扱う（1台→2台、2台→3台、3台→4台をそれぞれ別の背景画像にする）。

| Step | 設備（→ [03_equipment_tree.md](file:///Users/yoshihirohakuno/.gemini/antigravity/scratch/janso-story/docs/design/03_equipment_tree.md)） | コスト | 背景の状態 | 生成方式 |
| :--- | :--- | :--- | :--- | :--- |
| 0（初期） | ── | ── | 卓1卓・電球切れかけ・トイレ未修繕・床古い・壁紙黄ばみ・手積み卓 | （ベース画像） |
| 1 | 卓を1台追加（2台目） | 2,000両 | Slot-C（2.2節参照）に卓が出現。他の状態はStep0と同じ | 単体生成＋合成、または背景再生成 |
| 2 | 卓を1台追加（3台目） | 2,000両 | Slot-Bに卓が出現 | 単体生成＋合成、または背景再生成 |
| 3 | 卓を1台追加（4台目） | 2,000両 | Slot-Dに卓が出現。4卓が揃う | 単体生成＋合成、または背景再生成 |
| 4 | 電球を交換する | 500両 | 照明が明るくなる。暗がりが消え、4卓・壁の質感がはっきり見える | 背景ごと再生成 |
| 5 | トイレを修繕 | 1,200両 | トイレのドア・壁の劣化表現が消える | 単体生成＋合成（範囲限定なら可） |
| 6 | 床を新調する | 1,000両 | 店内全体の床がきしみ・劣化表現の無い綺麗な板張りに変わる | 背景ごと再生成 |
| 7 | 壁紙を変更する | 900両 | 壁の黄ばみ・劣化表現が消え、新しい壁紙に変わる | 背景ごと再生成 |
| 8（完成形） | 自動雀卓にする | 3,500両 | 4卓すべてが自動雀卓に切り替わる。Phase 1の内装としては最終形 | 単体生成＋合成（4卓分まとめて差し替え） |

各Stepは前の状態に積み重なっていく（Step5の背景はStep4の状態がベースになっている）ため、生成AIに画像を依頼する際は**「直前のStep of 背景画像」を毎回入力として渡し、そこに今回の変化だけを加える**という運用にする。これにより「組み合わせ」ではなく「連番」として管理でき、必要な背景画像はStep0〜8の合計9枚で済む（系列Bの小物を含めない場合）。

卓追加（Step1〜3）と自動雀卓化（Step8）は卓そのものの差し替えなので、卓部分のみの単体生成＋合成でも対応可能。電球交換・床新調・壁紙新調（Step4・6・7）は部屋全体の面に関わるため背景ごと再生成が基本だが、Step順が固定されている前提なら「常に直前の1状態からの差分」しか発生しないため、再生成の負荷は組み合わせ方式（最大8パターン）より大幅に少なくなる。

#### 2.3.3 系列B：小物の自由購入（レイヤー合成）

| 設備（→ [03_equipment_tree.md](file:///Users/yoshihirohakuno/.gemini/antigravity/scratch/janso-story/docs/design/03_equipment_tree.md)） | コスト | 背景への反映 | 生成方式 | 補足・指示の出し方 |
| :--- | :--- | :--- | :--- | :--- |
| **お茶サービス開始** | 300両 | カウンターに急須・湯呑みが追加される | 単体生成＋合成 | 「このカウンターの上に置く、和風の急須と湯呑みのセットを、背景と同じ画角・同じ照明トーンで」と指示し、カウンター上の決まった座標に合成 |
| **Wi-Fi設置** | 1,500両 | 壁にルーター、または窓際にアンテナ的小物が追加される | 単体生成＋合成 | 「壁掛けの古いWi-Fiルーター、背景と同じ照明トーンで」等を指示し、壁の決まった座標に合成 |
| **ドリンクバーを設置** | 1,800両 | カウンター付近に新しい設置物（ドリンクバー・カップ等）が追加される | 単体生成＋合成 | 「カウンターの一角に置く、簡易ドリンクバー（ディスペンサー・紙コップ・トレー）を、背景と同じ画角・同じ照明トーンで」と指示し、カウンター上の決まった座標に合成。お茶サービスと共存する配置にするか、置き換えるかは別途決める |
| **営業時間延長** | 0両（体力コスト） | 背景変化なし（時間帯演出のみ） | 対象外 | 夜間演出を別途行うなら、別途「背景ごと再生成（夜verベース画像）」として扱う必要あり。現時点では未設計 |

系列Bは系列Aの進行状況（Step0〜8のどの状態か）とは独立して、いつでも好きなタイミングで合成できる。実装上は「その時点の系列Aの背景（Step0〜8のいずれか）」の上に、購入済みの系列B小物レイヤーを重ねて表示する、という2層構成になる。

## 4. 今後の更新方針

* 本ファイルはPhaseが進むたびに「2. Phase 1」と同様の粒度（初期状態／スロット配置／購入対応表）で3章の各Phaseを埋めていく。
* 設備購入の背景反映を整理する際は、2.3.1節の「系列A（順序固定・内装の大きな変化）／系列B（自由購入・点的な小物）」の分類を必ず先に行う。系列Aは1本道の背景連番として扱い、組み合わせ爆発を避ける。Phase 2以降で2F・3Fが増える際も、フロアそのものが増える変化は系列Aの延長として扱う想定。
* スロット配置図はアスキー図でまず仕様を固め、最終的なビジュアルは別エージェントで画像化する（本ファイルはレイアウトの仕様書として機能し、画像生成のための仕様書を兼ねる）。
* 動線ルール（1.2節）はPhase共通の原則として、新しいフロア・部屋を設計する際も必ず最初に確認する。
